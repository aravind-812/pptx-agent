Meta-improve loop — how the system patches itself based on batch failures
1
Batch run completes — failures collected
eval_agent/benchmark.py runs all 44 transcripts through the full pipeline + 6 evals. Appends results to eval_agent/results/benchmark.jsonl with timestamp. Each line: transcript_id, all 6 eval results (passed/reasoning), executor_log summary, review_verdict.
↓
2
Failure threshold check
If any eval's pass rate drops below threshold (configurable per eval — e.g. hallucination >95%, sanitization >85%), auto_improve.py is triggered for that eval. Multiple failing evals → ranked by severity, worst first. Regressions vs previous baseline also flagged.
thresholds = { "hallucination": 0.95, # hard — never tolerate "placeholder": 0.99, # deterministic — should be near-perfect "faithfulness": 0.80, # key content must land "sanitization": 0.85, # no filler "completeness": 0.75, # most facts used "shape_coverage": 0.90, # executor must apply edits }
↓
3
Failure clustering
All FAIL cases for the target eval are collected. LLM reasoning strings are grouped by pattern (exact string matching + semantic clustering via Haiku). Cluster labels extracted: "company name replaced by generic", "percentage rounded", "filler phrase 'comprehensive' added", etc. Top 3 clusters passed to improvement step.
↓
4
Sonnet prompt surgeon
auto_improve.py sends to Sonnet: (a) current planner system prompt, (b) top 3 failure clusters with 3 example cases each, (c) instruction: "suggest a minimal, targeted addition to the prompt that would prevent these failures without over-constraining passing cases." Returns patch + reasoning + estimated affected count.
Prompt: agents/planner.py:SYSTEM_PROMPT Cluster: "company name replaced by generic" (14 cases) + COMPANY NAME RULE: If source contains company/product/person name, + use it VERBATIM. Never replace with "the customer" / "the platform".
↓
5
Human review in EvalLab UI (REQUIRED)
Patch is written to eval_agent/staged_patches/TIMESTAMP_sanitization.diff. Never auto-applied. EvalLab "Improve" tab shows the diff with all supporting failure cases. Reviewer approves or rejects. Rejected patches are archived for future reference.
↓
6
Apply + re-run + compare
Approved patch applied to agents/planner.py. Benchmark re-runs only the previously-failing transcripts (not all 44 — saves cost). Pass rate compared to pre-patch baseline. If target eval improved AND no regressions on other evals → accepted. If regression → patch reverted, staged again with regression context.
